# 🧠 THE PLAN — how to survive (and win) the 5-day assessment

> This is everything, in one place — the why AND the picture. One note file, not many.
> Personal notes — gitignored, never public.

---

## The root cause (read this first when you panic)

You don't have a discipline problem. You have a **"the task has no picture yet"** problem.
Paralysis, procrastinating, biting off too much, tasks feeling endless, overworking to
catch up — all of it comes from the same root: the project is an abstract cloud with no
image in your head. Once you can **see** it, you're a machine.

So the whole job is: **turn the assessment into one picture BEFORE you do anything else.**

---

## The core move: one story, not three tasks

The assessment is 3 deliverables (p2p app, launch thread, video) → for you that's 3
abstract mountains. Reframe as **one story with three acts**:

> "Here's a problem → here's the thing I built → here's how I built it → here's me showing it."

The app, the thread, and the video are the same story told three ways.
**Storyboard first, build second.** Write the story while it's cheap (before code), then
let the code fill in the storyboard — instead of the storyboard chasing finished code.

This also fixes the "endless, no checkbox" feeling: a story has a shape you can *see*
advancing.

## Day 0 ritual (before Monday)

Do this the moment you read the assessment. **No coding.**

1. **Draw the Map** (the road section above). One page. Left→right. If it's not a picture, it's not done.
2. **Pre-decide everything you can.** Paralysis = open decisions. Lock: what the app does,
   stack pieces, thread structure, video structure. Kill every choice today so Monday has
   zero "what do I do first."
3. **Define a small "done" + write the NOT-list.** Explicitly write what you will *not*
   build. This is your scope fence — it's what stops the overrun.

You already built **PearNote**. Decide now that this app is an evolution of that learning —
that removes the biggest decision (what to build) before the clock even starts.

---

## 📬 Day 1 — the moment the email arrives

**Do NOT start coding.** First ~90 minutes = orient, not build.
Paste the raw email into `assessment.md` (this one IS committed).

1. **Read it twice. Capture it verbatim.** Exact words, no paraphrase yet.
2. **Start the clock.** Note received date/time, compute the **5-day deadline**,
   write it at the top of the road / on the post-it.
3. **Extract requirements + constraints.** List every deliverable, the exact submission
   format, links/handles needed, any *required* tech/APIs, any stated scoring criteria.
   Separate **must-do** from **you choose**.
4. **Re-draw the road with the real specifics.** Fill the blank cells: problem, app,
   each checkpoint. The abstract cloud becomes a picture.
5. **Coverage check.** Map **every requirement → a checkpoint** on the road.
   A requirement with no checkpoint = a missing leg. Add it now, not at the end.
6. **Pre-decide the open choices.** Lock the app (PearNote evolution), stack, scope.
   Write the **NOT-list**.
7. **Do ONE tiny Level-1 block (45 min), then stop.** Smallest "app runs locally" action.
   End Day 1 with a visible win — commit + screenshot onto the road.
   *You're not behind; you started.*

**5-day rhythm (keep a buffer):**

| Day | Focus                                             |
| --- | ------------------------------------------------- |
| 1   | scope + **Level 1** (app runs)                    |
| 2   | **Level 2** (p2p sync)                            |
| 3   | **Level 3** (distribute + OTA)                    |
| 4   | **thread** + record video                         |
| 5   | **edit video + submit** ← buffer, no real work    |

## The daily loop (anti-paralysis + anti-overwork)

- **Tiny start, never a big start.** First action = 5 min max: open the map, mark where you
  are, do one 25-min block. The wall isn't the work, it's the *starting*. Make starting
  laughably small.
- **Time-box, don't task-box.** You under-estimate tasks, so tasks become 16h. Flip it:
  "I work 3 blocks of 90 min today." Stop when the blocks are done, even mid-task.
  The timebox survives; the task-list doesn't.
- **One visible win per day.** End the day with something that *exists* — a commit, a screen
  recording, a clip in the timeline. Photograph it onto the map (📌).
- **Never carry a task to tomorrow.** If it didn't fit, **shrink tomorrow's task** instead.
  This is the exact mechanic that stops the "plan is fucked up" cascade.
- **Sandwich the boring parts.** Hardest/ugliest technical bit FIRST (short) to break
  avoidance → then a creative task (script a video beat, draw a diagram) as the reward.
  Creative = flow for you. Use it as fuel, not as procrastination.

## When the freeze hits mid-project

You'll know: you drift to "stupid things." That's the signal the current step lost its
picture. **Stop. Go to the wall. Re-draw just that one step until it's an image again.**
The freeze is always a *missing picture*, not laziness. Solve it with a drawing, not
willpower.

---

## Two layers (don't merge them)

**Layer 1 — the giant post-it = THE PICTURE (understanding).**
"*What is this thing and where am I?*" Physical is perfect: your brain unlocks on drawing.
When you freeze, you don't think your way out — you **look up at the wall**.

**Layer 2 — GitHub repo + Projects = THE EXECUTION (and the deliverable).**
"*What's next, what's done?*"
- Make the repo **public**. Reviewers read your README + commit history like a portfolio.
  Commit early, commit often, messages that tell a story.
- README should read like a **mini-tutorial** — because "create technical content that
  educates developers" *is literally the job*. The repo is a free audition.

## 🗂️ The Kanban board (GitHub Projects)

**Columns — status, left → right:**

> 📋 Backlog → 🎯 Today → 🔨 Doing → ✅ Done

**Labels — for the phase (NOT columns):**

> `Map` · `Build` · `OTA` · `Thread` · `Video` · `Submit`

**Why status columns and not phase columns:**
- Phase-columns trap a card in "Build" for *days* → it feels endless again (your exact old trap).
- Status columns give **constant movement** — cards flow left→right every day.
- A growing **✅ Done** pile is the *visible proof you're advancing* = your dopamine fix.

**The rule:** every day, at least **one card hits `Done`.** No exceptions.
That's the board version of peeling a sticky off the post-it.

*Optional:* add a custom **`Phase`** field if you prefer filtering over labels — but labels
are the simplest thing that works. **Don't over-build this.**

## ⚠️ The trap to avoid

Setting up the terrain is **the most tempting procrastination you'll ever face.**
Perfect board, perfect labels, no app built. **Timebox terrain prep to ~90 min, then stop.**
Rough and real beats polished and empty. Don't *perform* organization — genuinely use it,
and impressive is a side effect.

## 🏁 Terrain prep — do now, ~90 min, then stop

1. Draw the post-it road (the road section above). App cells stay blank.
2. Public repo: README, LICENSE, .gitignore, one "Day 0: terrain" commit. ✅ done
3. Create the Projects board: **Backlog → Today → Doing → Done**
   (labels = road phases: Map · Build · OTA · Thread · Video · Submit).
   → full detail in **"The Kanban board"** section above.
4. Buy stickies. **Stop.**

## The three "levels" (so you don't double-count)

It's **one app**, three moments of maturity — not three products:

- **Level 1 — App runs:** opens, works locally, single machine.
- **Level 2 — App goes p2p:** syncs data with other peers. This is what people call
  "the backend," but it's just your app replicated over Hypercore. **No server exists.**
- **Level 3 — Distribute + OTA:** someone installs it from your link, and you push a new
  version over the air.

Same house: foundation → walls → roof. You only pass when all three are visibly true.
